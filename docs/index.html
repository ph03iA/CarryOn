CarryOn

A local Windows agent

Usage limits, handled locally

Keep your work going when the limit runs out

CarryOn is a small Windows program that watches your Claude Code and Codex plan usage every minute without sending a prompt. When a limit runs out it records the incident, waits for the reset, asks Gemini whether the cut-off session is worth continuing, and resumes that session by its ID. You get an email when the limit comes back and when the resumed run finishes.

Windows 10 or 11. Go 1.26 or newer. The watcher and the agents run on your own machine.

Part one

What CarryOn does

CarryOn reads plan usage from the tools you already use, with no prompt and no cost. A window that reaches 100 percent becomes one recorded incident, and the session that the limit cut off is identified from the local session logs. When the limit resets, CarryOn confirms the reset with a fresh reading, asks Gemini for a single decision, and, if the decision is to continue, runs the provider's own resume command against that session ID in the session's own folder. Incidents, resumes, decisions, and the email outbox are written to a local SQLite database, every decision is logged with its reason, and the two events worth knowing about, the limit coming back and a resumed run finishing, arrive by email.

Part two

How it works

  1. The limit hits 100 percent. CarryOn records one incident for that provider, window, and reset time, and notes the session log that the limit cut off. No email is sent when a limit runs out.

  2. The reset is confirmed with a fresh reading. The reset counts only when a new reading is taken after the reset time, is under two minutes old, is for the same account, and shows no window still at 100 percent with a future reset.

  3. Gemini decides. The tail of the cut-off session, the folder, the limit, and the reset time go to Gemini, which returns one decision: resume, skip because the task looks done, or skip because the agent looked stuck.

  4. The back email goes out. One email leads with the provider being back and says what CarryOn did, for example resuming your session in a folder, nothing to resume, or skipped with a reason.

  5. The session resumes by ID. The agent runs in the session's folder against that session's ID, so it continues the same conversation rather than the newest one in the folder.

  6. The finish email reports the result. When the resumed run ends, a second email carries the post-run decision, the agent's last message, and the files it changed.

Part three

How the agent decides

Resume
Unfinished work remains. Gemini returns a concrete next step, which becomes the prompt for the resumed run.
The session stopped mid-refactor with a failing checkout test and a clear next step. The reply is resume with: Run the failing checkout test and finish the handler.
Skip because the task looks done
The work appears complete, so no usage is spent on a resume.
The last assistant message says the change is complete and the tests pass. The reply is skip_done, and the back email reads: skipped: the task already looked done.
Skip because the agent looked stuck
The agent was looping or blocked, so a person should look instead.
The log shows the same file edited five times with the same error. The reply is skip_stuck, and the back email reads: skipped: the agent looked stuck.

Part six

Safety

  • A reset counts only after a fresh reading taken after the reset time, under two minutes old, for the same account, with no window still at 100 percent.
  • Resumes use the session ID, and CarryOn skips a session that was already continued after the cut-off.
  • Each limit hit allows at most two resumes for its cut-off session.
  • Claude, Codex, and the usage probes run inside a Windows job object with kill on close, so a CarryOn crash kills the agent and its children.
  • Both API keys are removed from every Claude and Codex process CarryOn starts.
  • Secrets are redacted from session text before it goes to Gemini, and email bodies are redacted again before Resend.

Part seven

Setup

Run these in PowerShell. You need Claude Code signed in with a Pro or Max plan, or Codex signed in with a ChatGPT plan, plus a Resend key and a Gemini key.

Build

$env:GOARCH = "amd64"
go build -trimpath -o carryon.exe ./cmd/carryon

Create the state folder and config

.\carryon.exe init

Put the keys in %APPDATA%\CarryOn\.env

RESEND_API_KEY=re_...
GEMINI_API_KEY=...

Run it in the foreground first

.\carryon.exe watch

Install the logon task

.\carryon.exe service install

Everyday commands

.\carryon.exe simulate
.\carryon.exe simulate codex
.\carryon.exe simulate --session <id>
.\carryon.exe log
.\carryon.exe reset

simulate picks the newest Claude Code session, or the newest Codex session with simulate codex. reset asks before deleting state; --yes skips the question.

The full README has the rest, including the config fields, the troubleshooting notes, and the known limits.

Part eight

Known limits

CarryOn is Windows only, and the Claude Code usage request it relies on is experimental, so a Claude Code update can change it. Print-mode permissions can still block edits. A machine that stays offline for a long time can lose or duplicate a queued email. The Claude cut-off fixture used by the tests is synthetic until a real cut-off is captured. The full list is in the Known limits section of the README.

Part nine

Privacy

Sent to Google

Gemini receives the tail of the cut-off session, about the last 4,000 tokens, plus the folder, the session ID, the limit and reset time, and the attempt count. After a run it receives the exit status, the diff stat, a bounded diff excerpt, test output when tests ran, and the last message.

Credential-shaped text is redacted before sending, and the session text is wrapped in delimiters that tell the model to treat it as data.

Sent to Resend

Resend receives the recipient, the sender, the subject, and the body of each email. The body holds the limit and reset time, the session ID and folder, the decision and its reason, the resume prompt, the agent's last message, the files that changed, and test output.

Email bodies are redacted again before they are sent.

Stays on this machine

Usage readings, incidents, resume records, decisions, the email outbox, the session logs, the configuration, and both API keys stay in %APPDATA%\CarryOn. CarryOn makes no other network calls.

It never opens ~/.claude/.credentials.json, ~/.codex/auth.json, or a keychain entry, and it never prints a token.
